# Stories — Firestore Security Rules

Source: `firebase/rules-src/firestore.rules.tmpl` + `firebase/rules-src/permissions.json` →
`firebase/firestore.rules` (generated by `npm run gen:rbac`; never edit the generated file). Tests:
`firebase/rules-tests/firestore.rules.test.mjs` (`npm run test:rules`).

## Principles

- **Deny by default.** A catch-all `match /{document=**}` denies everything not explicitly opened.
- **Clients read; functions write.** Every invariant-bearing document is written only by Cloud Functions (Admin SDK).
  Client writes will be allowed only for low-risk self-owned docs (e.g. notification `readAt`) as modules add them.
- **Authorization from claims** (`{ sa, o: { orgId: { r, b } } }`, see RBAC.md §4):
  - `inOrg(o)` — org isolation · `inBranch(o, b)` — branch isolation · `can(o, perm)` — RBAC via generated `perms()`
  - `isSA()` — platform Super Admin.
- **Queries must match rules.** A list query is only allowed if the rules can prove every result is readable, so
  repositories add the same filters (e.g. branch-scoped staff pass `branchIds array-contains-any <their branches>`).
- A generator guard refuses to emit a blanket `allow read, write: if request.auth != null`.

## Current rules (Phase 0)

| Path | Read | Write |
|---|---|---|
| `users/{uid}` | owner (`get`) | functions |
| `users/{uid}/memberships/{orgId}` | owner | functions |
| collection group `memberships` | `staff.view` in `resource.data.orgId`; branch-scoped viewers only rows overlapping their branches | functions |
| `orgs/{o}` | any role in `o` (`get`); Super Admin (`list`) | functions |
| `orgs/{o}/branches/*`, `orgs/{o}/departments/*` | any role in `o` | functions |
| `orgs/{o}/auditLogs/*` | `audit.view` in `o`; branch-scoped auditors only entries with their `branchId` | never (functions only) |
| `idempotency/*`, `platform/*`, `platformAuditLogs/*`, `orgs/{o}/branchCodes/*` | nobody | functions |

### Phase 1

| Path | Read |
|---|---|
| `books`, `authors`, `publishers`, `categories` | any signed-in user (`isbnIndex`, `counters` closed) |
| `orgs/{o}/copies/*` (+ `events`) | `books.view` at the holding **or** owning branch |
| `orgs/{o}/members/*` | `members.view` at the home branch |
| `orgs/{o}/subscriptions`, `loans`, `exchanges`, `reservations` | `members.view` at the record's branch |
| `orgs/{o}/payments` | `payments.view` at the branch |
| `orgs/{o}/depositAccounts/*` (+ `transactions` via the account), `depositAdjustments` | `deposits.view` at the branch |
| `orgs/{o}/transfers` | `books.view` at the sending or receiving branch |
| `orgs/{o}/plans` (+ `versions`), `config`, `branches/*/locations` | any role in the org |

A `get` of a document that doesn't exist is allowed with the module permission (it reveals only absence), so pages
can show "not found". `canAt()` checks "all branches" first so org-wide staff can list without a branch filter.
No client can write any of these.

## Tested guarantees

Org isolation, Franchise A ↛ Franchise B, branch isolation (audit + staff directory), self-only profiles, no client
role self-grant, default deny (even for Super Admin from the client); Phase 1: copies/members/loans/money
scoped to branch and role, franchise members invisible to other orgs and to corporate staff, transfers visible
to both ends, no client writes.

## Indexes

`firebase/firestore.indexes.json`: collection-group `memberships(orgId, branchIds CONTAINS)` and the collection-group
single-field index on `orgId`; `auditLogs(branchId, at DESC)`; index exemptions for audit `before`/`after`.
